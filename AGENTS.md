# Project instructions

- Be concise.
- Keep detailed documentation and assets local under `docs/`; only `docs/architecture.md` belongs in Git. Do not force-add ignored notes or assets.
- Maintain `docs/portfolio.md` as the living, portfolio-ready project overview and engineering case study. Update it when meaningful implementation, validation, performance, or scope changes occur.
- Keep the portfolio document human-readable and concise. Revise existing explanations rather than appending a session log; link to detailed engineering docs for depth.
- Distinguish implemented features, measured results, and future work. Every performance claim must identify its workload, device, measurement scope, and supporting result file. Preserve material limitations and credit reused models/libraries.
- Store useful portfolio figures and genuine screenshots in `docs/assets/`, embed them in the portfolio document, and preserve their source data or reproduction instructions. Never fabricate screenshots or measurements.
- Keep portfolio assets free of credentials, private local paths, and account-specific UI details. Public README links must point to tracked files.
